# MulleObjC-startup Library Documentation for AI
<!-- Keywords: startup, initialization -->

## 1. Introduction & Purpose

**MulleObjC-startup** is a minimal startup library that provides the required initialization code for executables linking against MulleObjC (and optionally higher-level frameworks).

**Key Features:**
- Provides `__register_mulle_objc_universe()` function for MulleObjC runtime initialization
- Minimal dependency footprint (MulleObjC, mulle-atinit, mulle-atexit)
- Deterministic initialization and cleanup
- Static library linking at build time
- Enables standalone Objective-C executables with MulleObjC (without Foundation)

**When to Use:**
- Creating MulleObjC executables without MulleFoundation
- Building lightweight Objective-C applications with basic classes (NSObject, NSThread, etc.)
- Custom startup code requiring MulleObjC root classes

**When NOT to Use:**
- For Foundation-based applications; use Foundation-startup instead
- When only mulle-objc-runtime is needed; use mulle-objc-runtime-startup

## 2. Key Concepts & Design Philosophy

- **Lightweight Startup**: Thin wrapper providing universe initialization for MulleObjC
- **MulleObjC Dependency**: Requires MulleObjC root classes (NSObject, NSAutoreleasePool, etc.)
- **Universe Initialization**: Single call to initialize mulle-objc universe
- **Deterministic Ordering**: Uses mulle-atinit and mulle-atexit for controlled startup/shutdown
- **Static Linking**: Compiled into executables; no runtime linking

## 3. Core API & Data Structures

### 3.1 Universe Initialization

#### `__register_mulle_objc_universe()`

**Function Signature:**
```c
struct _mulle_objc_universe *
   __register_mulle_objc_universe(
      mulle_objc_universeid_t universeid,
      char *universename
   );
```

**Purpose**: Initialize or retrieve the Objective-C universe for the current executable with MulleObjC support.

**Parameters:**
- `universeid` (uint32_t): Unique identifier for this universe (usually generated by mulle-clang)
- `universename` (char *): Human-readable name for debugging (e.g., "MulleObjC universe")

**Returns:**
- Pointer to initialized `struct _mulle_objc_universe`
- Universe includes MulleObjC root classes already registered
- Same universe instance for same thread/process

**Behavior:**
1. Initializes mulle-objc-runtime universe
2. Registers MulleObjC classes (NSObject, NSAutoreleasePool, NSThread, NSLock, etc.)
3. Sets up memory management and autorelease pools
4. Returns initialized universe ready for use

**Key Detail**: Idempotent—multiple calls return the same initialized universe.

### 3.2 Available Classes After Initialization

Once `__register_mulle_objc_universe()` completes, these MulleObjC classes are available:

#### Root Classes:
- **NSObject** - Standard root class for all objects
- **NSProxy** - Alternative root for dynamic proxies

#### Memory Management:
- **NSAutoreleasePool** - Batch memory management

#### Threading:
- **NSThread** - Portable thread abstraction

#### Synchronization:
- **NSLock** - Basic mutual exclusion
- **NSRecursiveLock** - Reentrant lock
- **NSCondition** - Wait/signal synchronization
- **NSConditionLock** - Condition with state

#### Method Introspection:
- **NSInvocation** - Message serialization
- **NSMethodSignature** - Method metadata

#### Core Protocols:
- **NSCoding** - Object serialization
- **NSCopying** - Copying support
- **NSFastEnumeration** - for-in loop support
- **NSLocking** - Lock protocol

### 3.3 Initialization Context

**What is Pre-Initialized:**
- mulle-objc-runtime universe
- All MulleObjC classes and protocols
- Memory allocation system
- Thread-local storage for autorelease pools

**What is NOT Pre-Initialized:**
- Application-specific classes (your own classes)
- Higher-level frameworks (MulleFoundation if not linked)
- Autorelease pool for main thread (you create it if needed)

## 4. Performance Characteristics

- **Initialization**: O(n) where n = number of MulleObjC classes (~15-20); typically <1ms
- **Memory**: MulleObjC classes + metadata (~100-200 KB)
- **Call Overhead**: Single entry point; cost paid once at startup
- **Runtime**: No ongoing overhead; normal MulleObjC performance

## 5. AI Usage Recommendations & Patterns

### Best Practices

- **Automatic Invocation**: mulle-clang automatically calls this via mulle-atinit; rarely needs manual invocation
- **Call First**: If calling manually, invoke before creating any objects
- **Main Thread**: Ensure called from main thread before spawning workers
- **Error Handling**: Check for NULL return; indicates universe initialization failure

### Common Pitfalls

- **Manual Calls**: Overriding automatic initialization is rarely needed; let mulle-clang handle it
- **Missing Main**: If manually calling and return is NULL, program should abort
- **Duplicate Calls**: Multiple calls with same ID return same universe (safe but unnecessary)

### Idiomatic Usage

**Pattern 1: Automatic (Recommended)**
```objc
// mulle-clang-compiled Objective-C code
// __register_mulle_objc_universe() called automatically before main()

#import "import.h"

int main(int argc, char *argv[]) {
    // MulleObjC universe is already initialized
    NSObject *obj = [[NSObject alloc] init];
    NSLog(@"Object: %@", obj);
    [obj release];
    return 0;
}
```

**Pattern 2: Manual Initialization (Rare)**
```c
#include <mulle-objc-runtime/mulle-objc-runtime.h>

int main(int argc, char *argv[]) {
    // Manually initialize (normally done by mulle-atinit)
    struct _mulle_objc_universe *u =
        __register_mulle_objc_universe(0xDEADBEEF, "MulleObjC");
    
    if (!u) {
        fprintf(stderr, "Failed to initialize universe\n");
        return 1;
    }
    
    // Now Objective-C code works
    return 0;
}
```

## 6. Integration Examples

### Example 1: Basic MulleObjC Application

```objc
#import <MulleObjC/MulleObjC.h>

@interface Person : NSObject {
    NSString *name;
}
- (id)initWithName:(NSString *)n;
- (void)greet;
@end

@implementation Person
- (id)initWithName:(NSString *)n {
    self = [super init];
    if (self) {
        name = [n retain];
    }
    return self;
}

- (void)greet {
    NSLog(@"Hello, I'm %@", name);
}

- (void)dealloc {
    [name release];
    [super dealloc];
}
@end

int main(int argc, char *argv[]) {
    NSAutoreleasePool *pool = [[NSAutoreleasePool alloc] init];
    
    Person *p = [[Person alloc] initWithName:@"Alice"];
    [p greet];
    [p release];
    
    [pool drain];
    return 0;
}
```

**Build & Run:**
```bash
mulle-sde add github:mulle-objc/MulleObjC-startup
mulle-sde craft
./build/Debug/app
# Output: Hello, I'm Alice
```

### Example 2: Using MulleObjC Threading

```objc
#import <MulleObjC/MulleObjC.h>

@interface WorkerThread : NSObject
- (void)runWorker;
@end

@implementation WorkerThread
- (void)runWorker {
    NSLog(@"Worker running on thread: %@", [NSThread currentThread]);
    for (int i = 0; i < 3; i++) {
        NSLog(@"  Step %d", i);
    }
}
@end

int main(int argc, char *argv[]) {
    NSAutoreleasePool *pool = [[NSAutoreleasePool alloc] init];
    
    WorkerThread *worker = [[WorkerThread alloc] init];
    NSThread *thread = [[NSThread alloc] initWithTarget:worker
                                                selector:@selector(runWorker)
                                                  object:nil];
    [thread start];
    
    NSLog(@"Main thread waiting...");
    [NSThread sleepForTimeInterval:1.0];
    
    [worker release];
    [thread release];
    [pool drain];
    return 0;
}
```

### Example 3: Using NSLock Synchronization

```objc
#import <MulleObjC/MulleObjC.h>

int main(int argc, char *argv[]) {
    NSAutoreleasePool *pool = [[NSAutoreleasePool alloc] init];
    
    NSLock *lock = [[NSLock alloc] init];
    
    if ([lock tryLock]) {
        NSLog(@"Lock acquired!");
        [lock unlock];
    } else {
        NSLog(@"Could not acquire lock");
    }
    
    [lock release];
    [pool drain];
    return 0;
}
```

### Example 4: NSAutoreleasePool Usage

```objc
#import <MulleObjC/MulleObjC.h>

NSString * processData(void) {
    NSString *result = [[NSString alloc] initWithCString:"processed"];
    return [result autorelease];  // Will be released at pool drain
}

int main(int argc, char *argv[]) {
    @autoreleasepool {
        NSString *data = processData();
        NSLog(@"Result: %@", data);
        // 'data' (result) released here at pool drain
    }
    return 0;
}
```

## 7. Dependencies

- **MulleObjC** - Provides NSObject, NSThread, NSAutoreleasePool, synchronization primitives
- **mulle-objc-runtime** - Core Objective-C runtime (transitive via MulleObjC)
- **mulle-atinit** - Deterministic initialization ordering
- **mulle-atexit** - Deterministic cleanup and shutdown

**No Additional Standard Library Requirements**
